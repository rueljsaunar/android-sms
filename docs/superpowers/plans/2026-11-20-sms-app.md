# Personal SMS App — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A private, single-user Android app that becomes the default SMS app and sends/receives real SMS over the SIM, matching six provided mockups in Material You.

**Architecture:** Single `:app` module, internally layered `data / domain / ui`. The system SMS provider (`Telephony.Sms`/`Threads`) is the source of truth for conversations, read live via `ContentObserver`→Flow. Room owns only app-private state: scheduled sends, drafts, archive flags. MVVM with Compose + ViewModels + coroutines/Flow.

**Tech Stack:** Kotlin 2.0.21, Jetpack Compose (BOM 2024.09.03), Material 3 / Material You, Room 2.6.1, Navigation-Compose, AlarmManager, AGP 8.5.2 / Gradle 8.9, JDK 21. No networking libraries; no INTERNET permission.

**Spec:** `docs/superpowers/specs/2026-11-20-sms-app-design.md`

## Global Constraints

- Kotlin, 100% Jetpack Compose, Material 3 / Material You dynamic color + full dark mode. Gradle Kotlin DSL.
- minSdk 24, compileSdk 34, targetSdk 34.
- No INTERNET permission, no third-party networking library — the app never touches the internet.
- Build pinned to **JDK 21** (set `org.gradle.java.home` or run with JDK 21; installed JDK 25 is too new for AGP 8.5).
- Palette tokens (verbatim): light bg `#FAF8FE`, received bubble `#EDEBF4`, sent bubble `#5A4BE0` white text, primary light `#5A4BE0`; dark bg `#121018`, surface `#1C1A24`, received bubble `#2A2735`, primary dark `#6457E6`, accent `#B4A8FF`. Bubble radius ~20dp with 6dp asymmetric corner on sender side; rows/cards 18dp; FAB/send button accent + soft shadow. Touch targets ≥44dp. No fake system status bar.
- Material You dynamic color on API 31+ overrides tokens; tokens are the <31 fallback.
- MMS / custom sender ID out of scope; leave a commented seam where MMS would slot in. Never attempt an alphanumeric sender.
- **Testing policy:** pure-Kotlin domain logic is covered by runnable JVM unit tests (`src/test`, JUnit4). Android-framework and Compose code is verified by `./gradlew assembleDebug` compiling cleanly plus visual match to the mockups; real send/receive/notifications are covered by the README device checklist (not runnable here).

## Review Focus

Inputs the spec implies but no happy-path test exercises, most likely to bite first:

1. **Permission denied / not default app** — every screen must render and not crash when READ_SMS/CONTACTS/SEND_SMS/POST_NOTIFICATIONS are denied or the app isn't default. (Covered: Task 14 degrade paths + Task 3 renders from empty data.)
2. **Unknown number (no contact match)** — rows/threads show the formatted number and a `+1`/initial fallback avatar, never blank. (Covered: Task 3 `displayName`/`avatarLabel` tests.)
3. **Multipart / very long message body** — must split via `divideMessage` and send as one logical message with one status callback set. (Covered: Task 8 compile + README checklist; Task 3 length handling.)
4. **OTP false positives** — a plain number in chat ("room 418") must not render a Copy chip; only messages that look like verification codes do. (Covered: Task 3 OTP detection negative tests.)
5. **Scheduled alarm after reboot** — pending schedules must survive a reboot and still fire. (Covered: Task 11 boot-receiver re-arm; README checklist.)
